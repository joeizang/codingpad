| D64 | **CodingPad ships an MCP server, `cpad mcp`, in a new milestone "MCP server" (0.3) between M5 and M6.** The user's own agents use CodingPad to run scripts, query allowed connections and read the library; CodingPad contains no AI. An MCP client is deferred to the in-app AI (D15). See [ADR 0008](adr/0008-local-mcp-server-for-agents.md). Amends D15, D33 and D34 | 2026-11-19 |
| D65 | The MCP server is **stdio only**: no HTTP/SSE transport and no listening port, so only an agent on the same machine, running as the user, can call it. `cpad mcp` reaches the running app over a local channel that rejects remote and other-user clients: a `0600` Unix socket with a peer-user check on Linux, and on Windows a named pipe with `PIPE_REJECT_REMOTE_CLIENTS`, a current-user-only security descriptor that denies the `NETWORK` SID, and a client-user check. Never TCP. **Its stdout carries only MCP messages**: every kernel and child (including Bun's raw fd 1/2 writes) is piped to the supervisor and becomes run output, and server logs go to stderr | 2026-11-19 |
| D66 | `cpad mcp` is **headless first**: it owns its kernels like `cpad run`. When the app is open, each agent run also shows in the window as a read-only agent run | 2026-11-19 |
| D67 | **Agent runs need no approval** (justified by D65). Every database connection is **off for agents until the user turns it on**, and `secret("name")` always fails in agent runs. **Credentials never enter the kernel**: the supervisor owns agent database connections and runs each query through a new `db_query` protocol request; the kernel holds only an opaque handle. Typed data contexts are not available in agent runs at first | 2026-11-19 |
| D68 | Read-only for agents has two levels. **Guarded** (default, protects against mistakes only): the supervisor parses each request and accepts only a single query (`SELECT`, `VALUES`, `EXPLAIN` without `ANALYZE`, PostgreSQL `SHOW`), rejecting transaction control, `SET`, `EXEC`/`CALL`/`DO`, `SELECT … INTO`, data-changing CTEs and cross-server functions; it then wraps the query in a read-only transaction on PostgreSQL, in a transaction it checks (`@@TRANCOUNT`) and rolls back on SQL Server, and in `mode=ro` plus `query_only` on SQLite. **Enforced** needs an optional **agent credential**, labelled enforced only after CodingPad checks its **effective privileges** (including inherited grants, sequence and column permissions, routine execution and ownership) on save, at MCP session start and on newly opened database connections. If verification fails or is inconclusive, agent access is blocked until verification succeeds or the user explicitly chooses guarded. SQLite can only be guarded. The UI labels each connection's level and lists any write paths found | 2026-11-19 |
| D69 | MCP runs return a **dump preview** (top tree levels, first ~20 rows) plus ids; agents fetch more with `expand_node` and `get_rows` over the protocol's lazy nodes and paging. Following D11, `cpad mcp` keeps **one warm kernel per script key** (the script's path, or an agent-supplied `session` name for inline source), at most 4 resident, evicting the least recently used; `cache()` never crosses script keys or the GUI. Rust keeps D11's exception: a fresh process per run, with a per-script disk cache separate from the GUI's. Rust inline caches are scoped to the MCP session. A run expires the previous dumps of its own script key, and other scripts' dump handles survive only while their kernel stays resident (eviction expires them); fetched pages are kept, and an expired handle returns an `expired` error. Unknown lengths are reported as `total: null, rowsSoFar, more`, never as the desktop's placeholder row. `get_rows` reads any range below the enumeration frontier and advances it forward by at most 1,000 rows per call. Kernel-backed expansion has a ten-second deadline | 2026-11-19 |
| D70 | Agents **read the library and the pinned folders but write only to an `Agent` folder inside the library**, created on first use; they cannot create, overwrite or delete anything else in the library or in a pinned folder | 2026-11-19 |
| D71 | **macOS release installers and the Homebrew tap resume in M5.8.** GitHub Releases distributes ad hoc signed disk images for Apple silicon and Intel. Development, required milestone acceptance checks and performance measurements continue to target Linux and Windows. Revises D62 | 2026-11-20 |
